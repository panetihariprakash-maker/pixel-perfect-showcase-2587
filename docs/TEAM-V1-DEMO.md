# Azure Ridge — Team V1 product demo

## Before presenting

1. Use a genuine guest account and a genuinely approved owner/property with an open room. Current production partner catalogue is empty; do not present sample stays as real inventory.
2. Choose future check-in/out dates with vacancy. Verify the assistant once before recording because Google service/quota availability varies.
3. Keep passwords/private keys out of the recording; do not show other guests' contact information or administrative credentials.

## Suggested 5–7 minute sequence

| Segment | Action and proof |
|---|---|
| Introduction | Explain guest planning/bookings, approved owner listings and separate staff access. |
| Home | Show resort photographs and preserved navy/teal/gold design; select Explore Rooms. |
| Rooms | Open an approved partner Room details view; show actual capacity, facilities and nightly rate. Sample stays are clearly labelled separately. |
| Connected API | Select dates in Request booking. Show returned vacancy, nights and total; review per-night seasonal rates. Explain this is actual database REST API output, not a Python claim. |
| Validation | Temporarily enter a guest count above capacity, show the error, then correct it. |
| Submit | Enter guest contact details, review prices and acknowledge no payment is charged. Submit once and show the saved reference. |
| Persistence | Open My Bookings, refresh, and show the same reference, amount and Requested status. It is not an accepted booking or a successful payment. |
| Dashboard | Show private request totals/pending count and aggregate available/occupied partner units. |
| AI | Ask about a known listed room or the sample Deluxe room; show the genuine streamed answer and its availability/payment caveats. If Google fails, show the actual error/Retry rather than substituting an answer. |
| Mobile | Resize to mobile; open/close sidebar and show Rooms/booking without horizontal scrolling. |
| Optional management | With separate approved owner credentials, show the submitted request; with authorized Super Admin credentials, show approval tools. Do not assign access in the recording. |

## Closing disclosure

Payments and shared operational persistence are not connected. Policies/contact/location still need official confirmation. Auth email/Google consent and complete privileged CRUD/upload demonstrations require external account interaction. The application uses its existing backend and real API; no external Python service has been invented.
